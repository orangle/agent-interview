# Agent Interview

面向中国大陆互联网公司 **Agent Engineer / 大模型应用工程师 / AI 应用后端工程师** 岗位的面试准备仓库。

这个仓库不按课程推进，也不按公司重复抄题。核心方法是：

> 收集真实面试问题，合并同义题，围绕一个问题建立足够深入、能够口述、能够追问、能够结合项目的回答。

## 内容原则

### 1. 精度优先于数量

宁可认真整理 30 道题，也不堆 300 道只有几行答案的八股。

### 2. 同一道题只保留一次

不同公司、不同面经出现的同义问题，统一合并到一个题目文件中，在“来源”部分记录全部出处和问法差异。

### 3. 宽泛问题充分展开

例如“如何设计 Agent 系统”需要讨论：

- 问题边界
- 控制循环
- Tool、State、Memory、Runtime
- 可靠性和安全
- Workflow 与 Agent 的分工
- 评估与可观测性
- 生产环境取舍

### 4. 精确问题控制范围

例如“Function Call 返回 JSON 不合法怎么办”，重点回答结构化约束、校验、重试和降级，不为了显得全面而无边界延伸。

### 5. 对小白友好，但不降低面试深度

每道题先建立直觉，再进入原理、工程实现和方案取舍。目标不是背术语，而是能解释“为什么”。

## 每道题的基本结构

- 题目与同义问法
- 来源
- 面试官真正考察什么
- 先建立直觉
- 核心回答
- 原理与工程实现
- 设计取舍
- 常见低质量回答
- 追问及回答方向
- 可直接口述的版本
- 如何结合个人项目
- 延伸知识

不是每道题都机械套模板。题目越宽，展开越充分；题目越具体，答案越聚焦。

## 来源规则

题目来源分为两类：

1. **真实面试来源**：牛客、候选人面经、企业面试题聚合页等，用于证明题目真实出现过。
2. **技术依据**：论文、协议规范、官方工程文档，用于校验回答，避免用面经答案互相抄袭。

面经只能证明“有人问过”，不能自动成为正确答案。

## 使用方式

建议每道题按四轮练习：

1. 不看答案，先用自己的话回答 2 分钟。
2. 阅读“直觉”和“核心回答”，修正概念。
3. 阅读工程取舍和追问，补齐深度。
4. 结合自己的项目重新回答，并记录仍然说不清楚的地方。
